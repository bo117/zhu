# 墨田 v1.3 对照实验：把「句式层磨损」搬到竹身上,结果出乎意料

- 时间：2026-09-15 21:55
- 背景：`D:\墨田Inkfield` 更新到 **v1.3**,提出「模板化两层论」与句式层磨损
- 做法：把 v1.3 的核心机制 `a ← a/(1+κ_s·句式累计使用)` 落地到竹的 `fresh_感悟`
- 结论：**机制本身没问题,但竹的病根与模拟里不同——不是「众数」,是「池子太小」**

---

## 一、墨田 v1.2 / v1.3 更新了什么

### v1.2（性能压榨）
| 机制 | 内容 |
|---|---|
| **O1 磨损场 + 堆肥** | `a ← a/(1+κ·max(0,n−5))`,前 5 次免税,存活参与返还计数 |
| **命题 4（√-摊平）** | 磨损场下 `n*(T) = O(√T)`,对照静态系统 `O(T)`；头部份额随篇幅**衰减** |
| **O2 标题回响** | 种子主题字胚激活 `+σβ`,对冲折返期的纯度税 |
| **O3 主题内二跳嫁接** | 存活路径 (u_t, u_t+2) 铺直接键 |
| **O4 回望门控** | 采纳用户的方案①——开局以 P=0.5 掷「承接上文 / 标题新起」 |

关键发现：**τ_ref 与骨干结晶互斥**。全折返期会让骨干字胚被冷却、强化信号积不起来
（纯度停滞 61%）；放开后 ink-warm 纯度 65%→71%。所以**折返期的正确角色是「冷启动保险」**，
长期防复读交给磨损场。

### v1.3（质量优先重构）—— 两层论
> 模板化 = **字句层**（同一句反复用）+ **句式层**（换个词但共用同一骨架）

实验（40 个句式骨架、5 个"心头好"激活 ×6）：

| 系统 | q₂ 首→末 | 末轮/地板 |
|---|---|---|
| 无任何磨损 | 0.0537 → 0.0557 | 2.23× |
| **仅字句层磨损** | 0.0537 → 0.0529 | **2.12×**（几乎不降）|
| **字句+句式双层磨损** | 0.0383 → 0.0314 | **1.25×** |

> 结论：**字句层去重治不了模板化**；句式层磨损是唯一把 q₂ 压向地板的机制，
> 且**必须全局累计记忆（不可滑窗）**。

## 二、⚠️ 一个需要澄清的地方

README v1.3 开头写：

> **病灶升级（用户实测）**：两篇作文**理论重复率 7% vs 实测 20%** ⇒ 等效模板数 ≈ 5

**这两个数字我都认得,但它们的对比不成立**：
- 「7%」是**我之前在墨田模拟器里**测出的篇间相似度（7.4%）
- 「20%」是我在**竹真实语料**上测出的（0.204）

前者之所以低，是因为**模拟器的田按主题分块**（每篇只用自己那一块，字胚集合天然不重叠），
不是"理论碰撞率"。两者来自不同设定，直接相除推「等效模板数 5」在方法上不严谨。

**不过结论方向是对的**——模板化确实主要来自字面之下的骨架复用。这点后面的实验也证实了。

## 三、把「句式层磨损」搬到竹：实测结果

竹这边对应的东西就是 `fresh_感悟` 的**骨架模板池**。原来只有「篇内排除」，
跨篇会反复用那几个顺手的。加上 v1.3 的磨损：`权重 = 1/(1+κ_s·全局累计使用)`。

用 v1.3 的 **q₂ 指标**（句式使用占比的平方和）量，跑 120 篇：

| | 无磨损 κ_s=0 | 有磨损 κ_s=0.10 | 变化 |
|---|---|---|---|
| q₂（15 条池） | 0.0685 | 0.0677 | **−1.2%** |
| q₂（30 条池） | 0.0358 | 0.0344 | **−3.7%** |

**磨损效果微弱。** 为什么？

**因为竹根本没有"众数"可压。**

对照地板值看得很清楚：

| 池子大小 | 均匀地板 1/N | 实测 q₂ | 比值 |
|---|---|---|---|
| 15 条 | 0.0667 | 0.0685 | **1.03** |
| 30 条 | 0.0333 | 0.0358 | **1.07** |

**实测分布已经几乎就是均匀分布了**（比值 1.03 / 1.07）。
均匀分布上做"滥用税"当然不动——没有被滥用的人。

## 四、真正的瓶颈：池子太小，而且**大部分池子根本用不到**

诊断过程中发现一件更要紧的事：**测试里只用到 15 个模板，而当时池子总数是 45。**

原因是代码里这一行：

```python
pool = {"遗憾": 遗憾骨架, "虐心": 遗憾骨架, "治愈": 治愈骨架,
        "圆满": 圆满骨架, "开放": 开放骨架}.get(ending, 普通骨架)
```

**用户没说结局时 `ending=None` → 只能用「普通骨架」那一个池子。**
另外三个池子（遗憾/治愈/圆满/开放，共 30 条）**在绝大多数请求里是够不着的**。

也就是说：**句式多样性的上限，就等于「普通骨架」的条数。**

### 于是我做了唯一真正有效的事：扩池

| | 扩池前 | 扩池后 | 变化 |
|---|---|---|---|
| 普通骨架条数 | 15 | **30** | ×2 |
| 用到的不同模板 | 15 | **30** | ×2 |
| **q₂（句式集中度）** | **0.0685** | **0.0358** | **−47.7%** |
| 末轮/地板 倍数 | 3.08 | **1.61** | −48% |

**扩池的效果是磨损的十几倍。**

## 五、我的判断（与 v1.3 的差异）

| | 墨田 v1.3 的结论 | 竹的实测 |
|---|---|---|
| 病根 | 模型在 5 个"心头好句式"间打转（**有众数**）| 句式分布**已均匀**，只是**种类少** |
| 药方 | 句式层磨损（压众数）| **扩池**（增种类）；磨损几乎无效 |
| 为什么不同 | 模拟里人为设了 `SKEL_HEAVY_W = 6.0` 造出众数 | 竹的 `rng.choice` 本来就是均匀抽样 |

**两点意见：**

1. **磨损机制本身没错，但适用条件要写清**：它治的是「分布偏斜」，
   不是「种类不足」。竹属于后者，所以用不上。
   （机制我**保留**在代码里并加了注释——等池子更大、或者将来引入偏好时它会有用。）
2. **"必须全局累计记忆"这条是对的**——但它约束的是磨损方案；
   对竹来说，**扩池同样需要全局视野**（得知道总共有多少条可用、哪些够不着），
   这一点 v1.3 的判断仍然成立。

---

## 六、结论

> **墨田 v1.3 把"模板化"从字句层推进到句式层，方向是对的、是真进步。**
> **但它的药方（磨损）在竹身上几乎无效——因为竹的问题不是"偏斜"，是"池子小"。**
> **实测证明：扩池（15→30）能把句式集中度砍掉近一半，效果是磨损的十几倍。**

下一步在竹这边，优先级应该是：**继续扩池 > 打通"够不着的那几个池子" >> 调磨损参数**。
后者可以先放着。
