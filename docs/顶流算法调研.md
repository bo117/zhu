# 竹 · 顶流后训练算法调研（2026）

> 面向「竹」这个小模型 + 单机 + LoRA 的场景，把 2026 年真正在用的后训练算法
> 逐条拆开，说明**选哪个、为什么、公式怎么写、坑在哪**。
> 本文所有结论都落到了可运行的代码里：见同目录 `GRPO训练.py`（含秒级自检）。

---

## 0. 一句话结论

竹现在的 `强化学习.py` 做的是 **RAFT（拒绝采样微调）**：
生成 K 篇 → 奖励打分 → 留高分 → 当普通 SFT 数据再训一轮。

这条路能用，但**本质还是模仿学习**——它只学会"高分样本长什么样"，
学不到"比现在好一点点的方向"。要往上走，正确姿势是换到
**GRPO 一族（组内相对优势 + 重要性比率裁剪）**，其中：

| 你的处境 | 选它 |
|---|---|
| 先跑通、代码最短 | `GRPO` |
| 要稳、序列长、工程化 | `DAPO` |
| **要最好的最终效果（首推）** | `GSPO` —— 序列级重要性比率，Qwen3 / GLM-5 在用 |
| 硬 clip 把样本梯度打成 0 | `SAPO` 软门控 |
| 想顺手把优化器也升级 | `Muon`（同算力约 2× 效率，只管大矩阵参数） |

竹是**序列级奖励 + 长文本生成**，两者错配正是 GRPO 不稳的根因，
所以**推荐直接上 GSPO**，而不是先 GRPO 再迁。

## 1. 竹现在的做法与瓶颈

`强化学习.py` 当前流程：

```
种子 → write_essay2 生成 K 篇 → compute_reward 打分（6 维，满分 10）
     → 保留 top ρ（≥7.5）→ 追加进 强化语料_rl.jsonl
     → 攒够 200 条就调 训练.py 做一轮 SFT
```

奖励函数的 6 个维度（原创度 2.5 / 细节密度 2.0 / 句长张力 1.5 /
情感克制 1.5 / 立意落地 1.5 / 结构 1.0）设计得不错，**奖励侧可以留用**。

瓶颈在**策略更新侧**，有三条：

1. **没有基线，只有绝对分**。7.5 分是好是坏？取决于这一批的平均水平。
   RAFT 丢掉的信息恰恰是"相对于本轮其他样本好多少"。
2. **没有重要性比率**。新策略与旧策略的偏移没有被约束，一次更新可能把
   模型带偏（要么原地踏步，要么崩）。
3. **奖励是序列级，损失是样本级**。序列级奖励 × 样本级损失，长文天然吃亏。

这三条，正是 GRPO 家族要解决的问题。

## 2. 算法族全景对比

| 算法 | 核心改动 | 解决什么 | 代价 |
|---|---|---|---|
| **GRPO** | 组内 G 条采样估基线，去 Value Model | 省一个 Critic，显存减半 | 长序列不稳 |
| **Dr.GRPO** | 去掉 std 归一化 | 消除"难题奖励被放大"的长度偏置 | 需要更稳的学习率 |
| **DAPO** | Clip-Higher + 动态采样 + Token 级损失 + 奖励整形 | 熵坍塌、无效组、长文稀释 | 超参变多 |
| **GSPO** | 重要性比率改成**序列级几何均值** | 奖励粒度与比率粒度对齐，长序列稳 | 实现要小心 |
| **SAPO** | 裁剪改**软门控** + 正负非对称温度 | 梯度永远不为 0，避免硬 clip 死样本 | 多两个温度超参 |
| **Muon** | 优化器：动量矩阵做 Newton–Schulz 正交化 | 大矩阵收敛快、省算力 | 嵌入/输出层仍须 AdamW |

## 3. 逐个拆开：公式与为什么

### 3.1 GRPO —— 基线

对同一个 prompt 采 G 条回答，用组内均值当基线，省掉 Value Model：

```
A_i = (r_i - mean(r)) / (std(r) + eps)
```

`A_i` 就是第 i 条回答的相对优势。正优势拉高概率，负优势压低。

**为什么有效**：同一 prompt 内采样，天然控制了难度变量——同一道题做对比，
比跨题比较公平得多。

### 3.2 Dr.GRPO —— 去 std 归一化

```
A_i = r_i - mean(r)          # 不除 std
```

**为什么**：除以 std 会**放大低方差组**（也就是难题、全对全错的边缘组）的梯度，
导致模型越来越爱啃难题、回答越来越长。去掉后优势就是朴素分差，更稳。

### 3.3 DAPO —— 四件套

**(1) Clip-Higher：上下界不对称**

```
clip(ρ, 1-ε_low, 1+ε_high)     # 典型 ε_low=0.2, ε_high=0.28
```

**为什么**：对称 clip 会压制低概率 token 的上升空间，熵一路掉到坍塌。
上界放宽给探索留路。

**(2) 动态采样**

```
if std(r) < 1e-6: 跳过这一组     # 全对或全错，优势全 0，白烧算力
```

**(3) Token 级损失**

分母用 **batch 内全部 token 数**，不是序列数。

**为什么**：用序列数平均，长序列每个 token 的梯度被 `1/|o_i|` 稀释，
模型会倾向于写短——这在作文场景是致命的。

**(4) 超长奖励整形**

超出目标长度的部分给软惩罚（不是硬截断），压制"越写越长"。

### 3.4 GSPO —— 序列级重要性比率（首推）

```
s_i = exp( Σ_t (logπ_θ - logπ_old) / |o_i| )
```

也就是逐 token 对数比率的**几何均值**，然后对这个 `s_i` 做 clip。

**为什么这是关键**：token 级比率连乘，方差随序列长度指数增长；
而奖励本来就是**序列级**给的。粒度不一致，就是 GRPO 在长文本上震荡的根因。
GSPO 把比率也压到序列级，两边对齐。

竹的作文动辄 800~1200 字，**这就是必须换 GSPO 的理由**。

### 3.5 SAPO —— 软门控

```
ρ_use = (1-ε_low) + (ε_low+ε_high) · σ( k·(ρ-mid)/half )
k_pos = 2,  k_neg = 6
```

**为什么**：硬 clip 把超出范围的样本梯度直接归零——样本白采。
软门控让越界样本**衰减而不是消失**，梯度永远不为 0。
负 advantage 用更大的 `k_neg`，让它更快饱和——因为我们不想花力气
去"抬高一个坏 token 的概率"。

### 3.6 Muon —— 优化器

对动量矩阵 `M` 做 Newton–Schulz 迭代近似正交化，再更新权重：

```
a, b, c = 3.4445, -4.7750, 2.0315      # 系数故意不精确收敛
O = a·M + b·(M·Mᵀ)·M + c·(M·Mᵀ)²·M
```

**注意**：这组系数是"最大化零点斜率"选的，`p(1) = 0.701 ≠ 1`，
输出是 `US'Vᵀ`（`S_ii ~ U(0.5,1.5)`），**不是** `UVᵀ`。
所以自检**不能**断言 `OᵀO = I`。该断言的正确性质是：

- 尺度不变（按 Frobenius 范数归一后，乘任意正数结果一致）
- 转置一致（`NS(G).T == NS(G.T)`）
- 输出有界（列范数落在 0.4~1.6）
- `p(1) == 0.701`

Muon 只用在 **2D 大矩阵**（attention/MLP 权重）；嵌入层、输出层、
LayerNorm、以及所有 1D 参数仍走 AdamW。

## 4. 三个必踩的坑

### 坑 1：`p_θ` 与 `p_old` 必须同一次前向口径

常见错误写法是"训一轮之后再算 old"。正确做法：

```
torch.no_grad() 下 前向一次 → 记 old_logprob（并冻结）
带梯度 前向一次           → 得 new_logprob
```

参考模型的 logprob 用 `model.disable_adapter()` 拿——**PEFT 场景下零额外显存**。
而且参考模型是冻结的，`ref_logprob` **可以缓存**，不必每轮重算。

### 坑 2：动态采样别忘

组内奖励全同 → 优势全 0 → 这一组梯度 0。不跳过就是在烧算力。

### 坑 3：奖励要可验证，且**把去重写进奖励**

前沿做法是「规则奖励 + ORM + GRM」三路混合，小项目用规则奖励起步完全够。

**对竹特别重要的一条**：生成类是复读的重灾区。语料里已有的句式会被模型
学成"标准答案"，越训越像。做法：

> 维护一个**篇级指纹库（SimHash + LSH）**，生成结果跟库里任何一篇撞车
> **直接判 0 分**。

这比事后过滤有效得多——事后过滤只是把废话删掉，
而写进奖励是**让模型自己学会避开**。

竹的 `语料指纹.py` 已经把这个库实现了，直接接进奖励函数即可。

## 5. 竹的落地改造方案

### 5.1 奖励函数改造（保留原 6 维，加两维）

```
R = 原有 6 维（原创度/细节密度/句长张力/情感克制/立意落地/结构）   # 满分 10
  × 0.9                        # 原有权重缩放
  + 1.5 × 去重奖励             # 与指纹库撞车 → 0；完全新鲜 → 1
  + 1.0 × 长度合规             # 落在目标字数 ±15% 内 → 1，超长软衰减
```

去重奖励直接用 `语料指纹.CorpusIndex.query()` 的相似度：

```
sim, meta, _ = 指纹库.query(生成的作文, threshold=0.62)
去重奖励 = 0.0 if meta else 1.0        # 撞车即 0
```

### 5.2 训练循环改造（RAFT → GSPO）

```
for step in range(steps):
    prompt = 抽主题
    outs   = 采样 G 条（G=8，温度 0.9，同一 prompt）
    rews   = [奖励(o) for o in outs]
    if std(rews) < 1e-6:  continue          # 动态采样跳过
    A      = rews - mean(rews)              # Dr.GRPO：不做 std 归一化
    old_lp = no_grad 前向（冻结）
    for epoch in range(mu):                 # mu=2~4
        new_lp = 带梯度前向
        s_i    = exp(mean_t(new_lp - old_lp))          # GSPO 序列级比率
        ratio  = clip(s_i, 1-ε_low, 1+ε_high)          # DAPO Clip-Higher
        loss   = -(A_i * ratio).sum() / 总token数       # Token 级损失
        + β · k3_kl(π_θ ‖ π_ref, 缓存)
        loss.backward(); opt.step()
```

### 5.3 自检清单（不加载模型，秒级跑完）

```
□ 优势组内零均值；全同分时优势全 0 且 std == 0
□ Dr.GRPO 的优势等于原始分差（不做归一化）
□ clip(1.5) == 1+ε_high；clip(0.5) == 1-ε_low（非对称）
□ GSPO 比率：200 个 token 全 1.1 倍时，序列级比率仍恒为 1.1（不连乘放大）
□ SAPO 门控：单调递增、值域有界、σ∈(0,1) 梯度永不为 0、负 advantage 更快饱和
□ k3 KL：同分布时为 0，且恒非负
□ Token 级损失等于单 token 目标；序列级平均会造成 1/|o_i| 稀释
□ Muon：尺度不变 / 转置一致 / 列范数 0.4~1.6 / p(1)=0.701
```
