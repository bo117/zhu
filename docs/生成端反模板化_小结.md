## 四、⚠️ 失败记录：段落节奏（已完全回退）

想打散「长度形状」，做法是让补字数集中到某几段。结果：

| 指标 | 加节奏前 | 加节奏后 |
|---|---|---|
| 骨架种类 | 29 | 39 ↑ |
| 前3骨架集中度 | 46.5% | 27.5% ↑ |
| **篇间相似度** | 0.233 | **0.416** ✗ 恶化 45% |
| **≥0.3 的文章对** | 19.7% | **87.6%** ✗ |

**原因**：把句子灌进同一段，反而放大了模板句的重复；且出现「一段极长、其余极短」的畸形。
**教训：长度形状不该在「补字数」这一层做**——骨架多样性不能靠牺牲句子分布来换。

## 五、本轮「obj 质量」修了什么（细节）

原来 `fresh_感悟` 从主线事件里取名词当 `{obj}`，有三层问题：

1. **词性判断太宽**：`wd.flag[0] == 'n'` 会把 `nr`（人名）、`ns`（地名）、`nt`（机构）
   全放进来 → 生成「那**奶奶**我还记得清清楚楚」。
   → 收紧为 `wd.flag in ('n', 'nz')`
2. **没有语义过滤**：时间词、方位词、称谓当"物件"用很别扭 → 加尾字/词表过滤
3. **模板假设 obj 是可触碰小物件**：`{obj}还摆在原来的位置。我没挪它…`
   遇到「医院」「座位」这类词就不搭。
   → 把依赖"小物件"的句子统一改成宽容句式（`跟{obj}有关的那些…`、`{obj}的事…`）

改完后同批产出的 `{obj}`：「手帕」「自行车」「座位」「医院」——都是完整词，
且句式都能接住。
