# 墨田（Inkfield）× 竹 —— 适配性分析

- 分析时间：2026-09-15 20:5x（后续版本变化见 §8 更新记录）
- 分析对象：`D:\墨田Inkfield`（README.md v1.4 / inkfield_sim.py / 结果报告.md）
  - 首次分析时版本为 v1.1；v1.2/v1.3 见 `墨田v1.3对照_句式层实验.md`，v1.4 见本文 §8
- 对照项目：`D:\竹`（中文作文生成「竹」）
- 结论速览：**适配度很高，但采用它会改变竹的技术底座。详见 §4 后果与影响。**
  - §1~§7 为 v1.1 原始结论，**至今未被推翻**；v1.2~v1.4 的增量见 §8。

## 1. 墨田是什么（一句话）

一套**不需要梯度下降**的生成系统：把"写作"从"在概率分布上采样"改成
"在加权有向图上做带代谢的生态演替"——字胚有地力（会耗尽、要冷却），
连接会被存活/死亡事件乘性修剪，跑题的连接会腐烂到消失。

它明确否定四样东西：**损失函数、梯度、值函数、极大似然**。

---

## 2. 关键证据：墨田治的病灶就是竹

墨田 README §0 列了"对自训练模型 400 万字输出的实测病灶"。
我在**竹自己的语料上独立复测**，结果对得上，而且更严重：

| 指标 | 墨田 README 记录的病灶 | 我在竹实测 |
|---|---|---|
| 单句最高份额 | 51.7%（「长大，是一瞬间的事。」） | 3 万篇里同壳稿大面积重合，去重去掉 **68.9%** |
| 句级重复 | 86.9% 的句子重复 ≥2 次 | **98.9%**（9342 篇 / 385,119 句 → 去重后仅 **4,361** 个不同句） |
| 标题失联 / 语体混杂 | 章节与标题无关，电竞腔混入 | 竹的 3 万篇本身就是**同模板批量生成**，无关篇目相似度中位数 0.42 |
| 记账失真 | 自报 225 万字 vs 实际 316 万字（差 40%） | 未测（竹不走这条链） |

> **385,119 句里只有 4,361 句是新的**——这不是"偶尔重复"，
> 这是墨田命题 2 说的"静态系统必然坍缩"的教科书级实例。
> 竹的复读不是"训坏了"，是**范式决定的**。

这一点很关键：它意味着**在竹现有的范式（语料 SFT + 采样生成）里加多少数据都治不好**，
因为病根在"无地力、无死亡、转移静态"。

## 3. 适配映射表

墨田没有"接口"，它是从零一套。但竹这边的组件几乎能一一对上：

| 墨田组件 | 规格 | 竹现有对应物 | 适配度 |
|---|---|---|---|
| **字胚 V**（意象/句式片段） | 内容 + 地力 + 生死计数 | `写作素材库.py`：`CAT_OPENERS` / `CAT_BITS` / `CAT_DEPTHS` / `CAT_CLOSERS`；`写作引擎.py` 的 `SCENE_OPEN`/`DIALOG_OPEN`/`SYMBOL_MOTIFS`/`MASTERS`；语料里 **4,361 个不同句** | ★★★★★ 现成 |
| **共现边 w_uv** | 开荒期从语料共现铺基权 | 可从 `训练语料_精编.jsonl`（9,342 篇，**已去重**）统计句-句/片段-片段共现 | ★★★★★ 可算 |
| **种子 s（标题）** | 内容匹配锚定，非学习所得 | `写作引擎.options()`：**74 个主题** + `写作素材库.CAT_TITLES` | ★★★★★ 现成 |
| **流域 B_s** | β^d，深度截断 ≤3 | `写作素材库.THEME_CATEGORY` 的主题归类可直接当邻域 | ★★★★ 现成 |
| **生死簿 R** | 外部规则判存活/死亡 | `写作引擎.overlap_check` / `_guard` + 蒸馏链里的"质检" | ★★★★ 现成 |
| **地力 f_v / 折返期 τ_ref** | f'=ρ(1-f)，τ=ln(1/(1-θ))/ρ | 无 —— 需新写（纯算法，约 30 行） | ★★★★★ 容易 |
| **生态乘子 m_e / 饿死** | 存活×λ₊、死亡×μ，用够次数且存活率低则除名 | 无 —— 需新写 | ★★★★★ 容易 |
| **嫁接**（生成新字胚） | 存活文本里的新组合切胚种回 | **无，且墨田自己也没实现** | ★★ **最大缺口** |

**一句话**：墨田缺的那个"会写新句子"的能力，竹这边也缺（竹靠神经网络补，
但这正是墨田要绕开的东西）。**两边正好卡在同一个地方。**

## 4. 后果与影响（重点看这里）

### 4.1 技术底座会变

| 会影响 | 怎么影响 |
|---|---|
| **Qwen LoRA 模型**（`output/merged` 730MB） | 墨田不训练神经模型。若全面采用，**这个模型在生成链路里就下线了** |
| **`GRPO训练.py`（我上一轮刚做的）** | **哲学对立**：墨田明确"无损失函数、无梯度"。两者是**互斥路线**，不能同时作为主线 |
| **`写作引擎.py` 规则引擎** | 反而**最契合**——它本来就是"片段拼装"，墨田恰好是"拼得更聪明" |
| **语料去重工作** | **仍然有用且必需**——墨田开荒要从干净语料挖共现，98.9% 重复的语料会把田种歪 |

> 直白说：**采用墨田 ≈ 承认"训模型"这条路对写作任务性价比低，改走"结构化重组"。**

### 4.2 能力边界变化（最大的两个风险）

**风险 A：内容会枯竭。**
墨田**不会生成新内容**，只能重组已有字胚。当前字胚池 ≈ 4,361 个不同句，
而竹有 **74 个主题** × 多种文体 → **平均每主题不到 60 句**。
墨田唯一的"长新东西"通道是**嫁接，而它自己还没实现**。
（README §9 也承认："嫁接未模拟，'学新'能力未测"。）

**风险 B：优化目标不等于"写得好"。**
墨田优化的是**纯度（不跑题）+ 不重复**，不是文采。
README §9 原文："不验证大规模文本质量"。实测 ink 的章节**存活率只有 7%**——
意味着大量章节被判"死亡"。直接接生产，可能出现
**"不跑题、不复读，但平淡"** 的文章。

### 4.3 预期收益（如果适配成功）

- 复读率从 **51.7% → 理论上界 3.6%**（墨田实测 ink 全程 0.76%），
  这是**数量级的改善**，而且是**结构性保证**，不是"训出来的"
- 两道防线时间尺度互补：**折返期即时**（第 1 章就生效，不依赖学习）、
  **饿死永久**（除名不可复活）
- 副作用惊喜：金句枢纽被清除**不需要任何规则指认它是病原**——
  是"与死亡强相关 → 连接腐烂 → 饿死"的副产物

### 4.4 工程成本

- 新增一套"田"的持久化（字胚图 + 地力 + 生态乘子 + 生死账本）
- 开荒一次：从 9,342 篇挖共现，估计分钟级
- 与现有链路**可以并存**（见下）

## 5. 推荐的适配路径（三选一）

**方案 A（推荐）：墨田当"选句器"，不推翻现有框架**
把 `写作引擎.py` 里现在的"随机挑选 + `_THEME_LAST` 轮换"换成墨田的地力+流域+指数赛跑。
- 保留现有体裁/技法/结尾体系
- **直接白拿"复读上界"的数学保证**
- 出问题可一行回退 → **风险可控**
- 改动量：小（一个选择函数）

**方案 B：墨田 + 神经模型分层**
墨田负责"骨架与选段"（保证不跑题不复读），神经模型只负责"局部润色"。
- 保住神经模型的价值
- 但要处理两套系统的接口，工程量大

**方案 C（不推荐立即做）：全面替换**
放弃 LoRA 与 RL 路线，全量走墨田。
- 收益未验证（大规模文本质量没测），代价确定（丢模型）
- 建议等墨田 v2 把"嫁接"补上再考虑

## 6. 仍需验证的点

1. **字胚粒度**：墨田模拟里"字胚"= 意象/句式片段，L=60 步/章。
   竹要写 800~1200 字 → 若字胚取句子，约 20~35 步/篇，比模拟短，需要重标定 τ_ref。
2. **生死簿质量**：README §9 明说"规则错，田就长歪"。竹的质检规则是否够严需实测。
3. **嫁接未实现**：这是能否长期跑的关键，两边都缺。
4. **A/B 实测**：建议用 `GRPO训练.py` 里那套奖励函数（含**去重奖励**）
   给墨田产出打分，与现有引擎产出做对照——**同一把尺子量两套**。

## 7. 一句话总结

> 墨田不是"又一个训练算法"，它是**换了一套世界观**：把"复读"从"要学出来的目标"
> 变成"结构上不可能发生的事"。竹的实测数据（98.9% 句级重复）证明竹**正好是它的靶子**。
> 适配技术上很顺（资源几乎现成），但**采用它意味着承认"训模型"这条路的性价比问题**，
> 并且短期内容多样性会受限于字胚池。
> **建议先走方案 A（当选句器）**，用同一把奖励尺子做 A/B，再决定要不要走到 B/C。

## 8. 更新记录

> 本节为增量记录。§1~§7 的结论保留不动，此处只写"改了什么、对适配结论有无影响、成熟度到哪"。

### 8.1 v1.1 → v1.2（性能压榨）—— 2026-09-15

**变化**：新增四项机制 O1 磨损场（`a ← a/(1+κ·max(0,n−5))`，前 5 次免税 + 存活返还"堆肥"）、
O2 标题回响、O3 主题内二跳嫁接（`(u_t,u_{t+2})` 铺键，跨主题不盖章）、O4 回望门控
（吸收用户方案①，章节衔接）；并给出**命题 4（√-摊平）**：磨损场下头部用量 `n*(T)=O(√T)`，
对照静态系统 `O(T)`——**头部份额随篇幅衰减**，实测 α=0.59（静态 0.99）。

**结构性发现（对竹重要）**：**τ_ref 与骨干结晶互斥**。全折返期会把骨干字胚一并冷却，
强化信号积不起来（纯度停滞 61%）。所以：
- **折返期的正确角色 = 冷启动保险**（第 1 轮金句份额 1.9%，对照 ink-fast 10.0%）
- **长期防复读交给磨损场**（软约束，命题 4）
- 推荐配置 `ink-warm`（τ 仅冷启动 2 轮）：纯度 65%→71%、存活率 26%、跨章衔接 44%

**对适配结论的影响**：**加强**。§4.3 预期收益里的"两道防线"现在有了更清楚的形态，
且 O4 回望门控正好对得上竹的章节结构需求（竹是 800~1200 字单篇，回望门控可当段间衔接）。
**代价要记住**：暖启动有**一个过渡轮**（第 3 轮头部冲到 8.33%），硬上界只在折返期生效期内成立，
之后靠磨损场软约束。竹若采用，`tau_ramp` 是要调的旋钮。

### 8.2 v1.3（句式层模板化）—— 已于竹侧实证，**结论与墨田不同**

**变化**：提出**模板化两层论**——字句层（同句复用）+ **句式层（同骨架换词）**，
后者此前所有去重机制"全瞎"；给出句式层磨损 `a ← a/(1+κ_s·句式累计使用)`，
实测把 `q₂` 从 2.23× 地板压到 1.25× 地板。

**竹侧实证（详见 `墨田v1.3对照_句式层实验.md`）**：机制本身成立，但**在竹身上几乎无效**
（`q₂` 仅 −1.2% / −3.7%）。原因是**竹的句式分布本来就是均匀的**（实测/地板 = 1.03、1.07），
**没有被滥用的人，滥用税自然收不上来**。竹的病根不是"众数偏斜"，是**池子太小**。
实测：**扩池（15→30 条）把 `q₂` 砍掉 47.7%，效果是磨损的十几倍**。

**对适配结论的影响**：**分流**——墨田的"必须全局累计记忆不可滑窗"这条判断在竹这边**成立且有用**，
但它的**药方（磨损）在竹上优先级很低**；竹的正确优先级是 **扩池 > 打通够不着的池子 >> 调磨损参数**。
（现状核对：`写作引擎.py` 的 `普通骨架` 已扩到 30 条，`遗憾/治愈/圆满/开放` 共 30 条
仍被 `ending` 分支锁住——`ending=None` 时只走普通池，**这 30 条还是够不着**。）

### 8.3 v1.4（质量梯度实验：序数生死簿）—— **诚实的负结果**

**变化**：v1.2 的生态只有"生死"没有"优劣"（好 10 分的章和好 6 分的章强化一样），
于是引入质量分
`Q = 0.35·纯度 + 0.25·流动 + 0.25·全局新颖 + 0.15·章内多样`，
并对比四种选择压（无 / 二进制 / 线性序数 / 截断式序数），唯一变量为选择压形式：

| 选择压 | 质量 Δ（8 轮） |
|---|---|
| 无生态 | +0.004 |
| 二进制生死簿 | +0.015 |
| 线性序数 | +0.013 |
| 截断式序数 | +0.004 |

**四种全部无显著质量爬升。** 墨田自己给的归因有两条，而**第②条是对竹最有价值的一句话**：

1. **评分维度饱和**——流动项两轮内触顶，新颖性项被有限池枯竭拖低，分数被结构性压平，
   任何选择压都无从区分；
2. **规则裁判太弱**——**"质量不是纯规则可判的标量"**，
   并提炼为：**「生态的价值上限 = 裁判的上限」**。

**墨田据此改变了路线主张**：下一步不再加旋钮，而是**离开玩具**——
① 接入**真实作文语料 + 真实裁判（人工/模型评分）**；
② 评分维度改用**不饱和的排名分**而非绝对值；
③ **明确承认嫁接（学新）与跨章结构两道闸仍未实现**，
   它们是"质量的天花板，不是旋钮能补齐的"。

**对适配结论的影响**：**三条，两好一坏。**

1. **§4.2 风险 B 被显著加强，且给出了机理。**
   原先只是"墨田优化的是纯度+不重复，不等于写得好"，
   现在升级为结构性判断：**生态能长到多好，顶多等于它那把尺子能判多好**。
   竹已有比玩具强的裁判（`写作引擎.overlap_check` / `_guard` + `GRPO训练.py` 的奖励函数，含去重奖励），
   但**仍是规则裁判**——所以对墨田在竹身上的预期应当**明确锁定为
   "不跑题、不复读，但不保证不平淡"**，不要期待它自己长出文采。

2. **v1.4 要的"离开玩具"，竹正好就是那个环境。**
   墨田缺的两样——**真实作文语料**和**真实裁判**——竹这边**都是现成的**
   （`训练语料_精编.jsonl` 9,342 篇已去重；`GRPO训练.py` 奖励函数是一条完整的外置评分链）。
   换言之：**竹不只是墨田的适配对象，还是墨田 v2 唯一可用的验证场。**
   这也把 §6.4 的"A/B 实测"从"可选验证"提级为**决定成败的那一步**——
   它不是验收环节，它是墨田在竹身上唯一能拿到质量信号的来源。

3. **这不改变 v1.1 的核心结论，但推迟了"全面替换"。**
   命题 1~3 的**去重结构性保证**（§4.3）丝毫未动，仍成立；
   但 v1.4 是一次**负结果 + 路线转向**，它**没有推进那两道闸**（嫁接、跨章结构）。

### 8.4 成熟度判断与结论

| 路径 | 成熟度 | 理由 |
|---|---|---|
| **方案 A：墨田当"选句器"** | ✅ **已可交付用户决策** | 依赖的是 v1.1~v1.2 的命题 1/4 与磨损场，**v1.3/v1.4 均未推翻**；改动量小（一个选择函数）、可一行回退；收益是**数学保证**而非训练所得 |
| **方案 B：墨田 + 神经模型分层** | ⚠️ 未成熟 | 需要接口工程；且 v1.4 证明质量得靠外置裁判，分层后"谁负责质量"更绕 |
| **方案 C：全面替换** | ❌ 明确不成熟（v1.4 反而更不推荐） | **嫁接（学新）仍未实现**——池里没有的表达长不出来，系统仍是重组器不是发明者；**无跨章结构**；**质量上限 = 裁判上限**，玩具层面已证明旋钮补不了 |

**最大缺口未变**（§3、§6.3 的判断仍然有效）：**嫁接两边都缺**。
v1.4 把"够不着的那 30 条结局骨架"和"嫁接"一同列为质量天花板——**都是从"重组"走向"生成"才解得开的问题**。

**一句话**：v1.4 是一份**负结果**，但它把墨田的**真实边界第一次说清楚了**——
它保证的是**不重复、不跑题**（结构性、可信），它**不保证写得好**（那取决于裁判）。
对竹的落地顺序因此更明确了：
**先按方案 A 试点，把 `GRPO训练.py` 的奖励函数当尺子做 A/B；
质量若不过关，问题不在墨田的旋钮，而在尺子——而那正是竹能补上、墨田补不上的那一环。**

**二、代码级变化（逐行 diff 得出）**

1. **新增"句式指纹"全局硬拦截**（核心）：`TAIL_N=10`（取句尾 10 字作指纹）、`TAIL_POOL=300`、
   `tails` 集合**跨章跨批**持久化进 state；生成时 `if texts[j][-TAIL_N:] in tailset: continue`。
   注意它是**硬禁用**，不是磨损、也不是折返期冷却。
   → **这正是 v1.5 对照实验里唯一有效的那个杠杆**（句式层折返 11.1% → 0.0%），
   **已被吸收进主循环**。这是本轮最有分量的改动。

2. **修复了一个致命 bug：「序数选择压」此前是死的。**
   旧版 `gen_chapter` 的函数签名里**根本没有 `mult` 参数** ——
   `score` 分支把 `mult` 写进 `loop_state.json`，但生成端**从不读取它**。
   也就是说 **v1.5 的人机闭环有一半是空转的**：分数进了状态文件，却对生成零影响。
   （旁证：`loop_state.json` 里 `mult == {}` 至今为空。）
   新代码把邻居权重预算成 `nbr_map`，并在构建邻居时就乘 `mult.get(key, 1.0)` ——
   **强化路径第一次真正接通**。顺带把旧代码在候选循环里**每轮重扫整个 bonds 字典**（6,551 条 × 每步候选）
   的 O(n²) 写法改成预算映射，也快了一个量级。

3. `batch_edges` 键类型做了防御（`str(ch_i)` / `ch_i` 都试）。**但没修完**：
   `st["batch_edges"]` 仍是直接下标，而 `load_state()` 的默认值 `{"uses":{},"mult":{},"round":0}`
   **不含 `batch_edges`** → 全新状态下先跑 `score` 依然 KeyError。（我已复核确认。）

4. **引入新 bug：指纹记忆池语义错误。** `st["tails"] = list(tails)[-TAIL_POOL:]` ——
   `set` 转 `list` 的顺序由**哈希**决定、**不是插入顺序**，所以截取到的是**任意 300 个**，
   而不是"最近 300 个"。后果：刚刚用过的指纹可能被随机丢弃 → **老句子有概率复活**。

**三、新工具（本轮真正的重点）**

`gui_scorer.py` 与 `web_scorer.py` 是**同一套逻辑的两个前端**（tkinter / 纯标准库），做的是：
> 自动生成 300 篇作文入 SQLite → 人在浏览器/窗口里按键盘 `1/2/3/4/5` 打分 → 导出 JSON。

- 生成端与 `loop_human.py` 同源（同 THEMES、同 `KAPPA=0.12 / GRACE=3 / OUT_W=0.25 / TAIL_N=10`），
  但**不含 `mult`** → 评的是**未强化的干净基线**（这其实是好事：可直接当 A/B 的 baseline 臂）。
- DB schema：`essays(id, theme, text, score, scored, scored_at)`。

**四、我在 `essays.db` 上的独立实测**（300 篇 / 2,251 句，非玩具规模）

| 指标 | essays.db 实测 | 竹现状对照 |
|---|---|---|
| 句级重复率 | **0.0%**（2,251 句全部互不相同） | 59.7% |
| 句尾 10 字指纹撞车 | **0.0%** | — |
| 8 字子串出现 >3 次 | 15 个（`走在回家的路上，`×5、`在我成长的道路上`×5、`长大，是一瞬间的`×4） | — |
| 主题关键词完全缺失（跑题） | **110 / 300 = 36.7%** | 竹「不跑题」0.8231 |
| 已评 / 均分 | 51 / 300，**均分 1.06**（49×1分、1×2分、1×3分） | — |

三条解读：

- **好：字句层与句尾指纹层双双做到 0.0%。** 尾-10 指纹在 300 篇规模上完全生效 ——
  这是"结构性保证"**第一次在真实语料、非玩具规模下被复现**，比 v1.4 的模拟结果硬。
- **新发现（比 v1.5 更细一层）：模板化至少是三层，第三层在漏网。**
  尾-10 指纹只管**句尾**，把前半句换掉照样复读 —— 实测残留的正是
  `走在回家的路上，` / `在我成长的道路上` / `长大，是一瞬间的` 这类**套话短语**。
  即：**字句层 ✅ / 句尾骨架层 ✅ / 套话短语层 ❌**。
  v1.3 的"两层论"应修正为**三层论**。**这是本轮最有价值的新发现。**
- **坏：跑题 36.7%。** 生成器的主题分派是"关键词命中数 argmax"，未命中一律归「通用」，
  且主题池为空时会 fallback 到**全部非通用句** → 主题约束形同虚设。
  在"不跑题"这一维上，**竹（0.8231）明显强于墨田当前实现**。

**五、闭环断点（距落地最硬的一条）**

DB 里**没有句子索引、没有 `batch_edges`**，存的是拼接后的纯文本；
`export_scores` 只导出 JSON，注释写"供墨田生态后续吸收"——**吸收器没有实现**。
链条是：**打分收集（人）✅ → 导出（工具）✅ → 回灌更新田（缺失）❌**，断在最后一步。

`loop_state.json` 里 `mult == {}` 正是佐证：**CLI 路径跑了 3 批，从未成功打过分**
（旧版 `py loop_human.py score 7,8,6,9,7,5` 的手工摩擦没人愿意付）——
**这恰好解释了为什么要造 GUI/Web 版**。

但**可补救性很好**（实测结论）：DB 内 2,251 句的句尾 10 字指纹**互不重复** →
只要重跑一次 `load_corpus()` 建 `tail → index` 映射，就能把每篇的分数**反查回字胚索引序列**，
进而算出 `batch_edges` 喂进 `mult`。
**缺的是一个约 40 行的"吸收器"，不是缺数据。** —— 这是目前投入产出比最高的一块。

**关于那 51 条分数**：**需谨慎，不应直接当人工质量判断。**
49 个 1 分高度符合"自动化测试时连按 1 键"的特征（`essays.db` mtime 22:49 距 `web_scorer.py` 22:45 仅 4 分钟）。
但它提出了一个真问题：**若真人打出来的分布也压在 1 分，说明"不重复"和"能读"之间还差得很远。**
