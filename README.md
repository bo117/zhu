# 竹 · 中文作文写作 AI

基于 Qwen2.5 的中文作文写作系统。两条生成路径并存：**规则引擎**（本机秒级出文，无需 GPU）与**神经模型**（LoRA 微调，走本地推理服务）。

> 代码、模型、数据分别放在三个仓库：
> - 代码：<https://github.com/bo117/zhu>
> - 模型：<https://github.com/bo117/zhu-model>
> - 数据：<https://github.com/bo117/zhu-data>

## 两条生成路径

| 路径 | 入口 | 依赖 | 说明 |
|---|---|---|---|
| 规则引擎 | `写作引擎.py` → `write_essay2()` | 纯 Python | 模板 + 句库**现场组装**（两槽位 × 连接词做笛卡尔积），秒级出文 |
| 神经模型 | `本地模型服务.py`（OpenAI 兼容，`127.0.0.1:8766`） | GPU 推荐 | Qwen2.5 + LoRA；`阿呆.py` 是客户端 |

`写作引擎.py` 里 `LOCAL_WRITER=1` 时优先走神经模型，服务不在线则自动回退规则引擎。

## 目录

```
写作引擎.py        规则引擎主文件：narrative2 生成、结构折返期、主题→物件绑定
作文引擎.py        议论文侧引擎（ANALYSIS / ARG_FILL / ARG_BODY 槽位）
写作素材库.py      句库与素材
高分作文库.py      真实范文库
写作流程.py        多轮写作流程（大纲 → 成文 → 改稿）
本地模型服务.py    OpenAI 兼容推理服务，含推理强度 EFFORT 三档
阿呆.py            桌面端 / 客户端
训练.py            LoRA SFT（QLoRA 4bit / 全精度，CUDA / ROCm / CPU 自动适配）
GRPO训练.py        GSPO 后训练（序列级比率 + Dr.GRPO 优势 + DAPO Clip-Higher）
语料指纹.py        MinHash + LSH 去重
错字分流.py        语料清洗（错字 / 语病 / 统计栏）
口语诊断.py        八类病灶的确定性路由（道德绑架 / 生硬 / 空泛 / 套话 …）
结构体检.py        评测尺子：篇间相似度、骨架种类、句级重复、首尾重合
择优选择.py        K 候选择优（多样性选择器，非质量裁判）
docs/              设计与实验记录
```

## 快速开始

```bash
pip install -r requirements.txt

# 1) 规则引擎直接出文（无需模型）
python -c "import 写作引擎; print(写作引擎.write_essay2('父爱', 800))"

# 2) 起本地推理服务（需要 zhu-model 仓库的权重）
python 本地模型服务.py            # 默认 127.0.0.1:8766

# 3) 启动完整程序
python 启动竹.py
```

配置文件 `配置.json`（仓库里是脱敏的 `配置示例.json`）：

```json
{ "api_key": "", "base_url": "https://token.sensenova.cn/v1", "model": "deepseek-v4-flash" }
```

## 训练

```bash
# 单卡 LoRA SFT
python 训练.py --preset 魔搭36 --max-hours 30

# 双卡
torchrun --nproc_per_node=2 训练.py --preset 魔搭36

# 只吃蒸馏语料 + 真人范文（排除模板语料）
python 训练.py --distill-only

# LoRA 后训练：GSPO
python GRPO训练.py
```

关键约定（都是踩过坑之后定下来的）：

- **奖励里写进去重**：生成结果撞语料指纹库判 0 分，让模型自己学会不复读。
- **GSPO 用序列级重要性比率**：作文 800~1200 字，token 级连乘方差爆炸。
- **优势用 Dr.GRPO**（不做 std 归一化）；**裁剪用 DAPO Clip-Higher**（`ε_low=0.2, ε_high=0.28`）。
- **损失按 token 级归一**，分母是总 token 数，否则长文被 `1/|o_i|` 稀释。
- MoE 基座只挂 attention 的 `q/k/v/o_proj`，**不要挂 `mlp.experts.*`**（一层 128 个专家，必崩）。
- 断点校验**信张量形状不信文件名**：旧 checkpoint 混进来会在 `load_state_dict` 报形状错，
  自动重试会带着同一个脏断点连炸。

## 评测

`结构体检.py` 是统一的尺子，改完必量：

```bash
python 结构体检.py --n 120 --seed 99
```

输出：篇间相似度（均值 / p99 / ≥0.3 占比）、骨架种类与集中度、句级重复率、字数达标率。

参考结果（120 篇 / seed 99，规则引擎去模板化前后）：

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 篇间相似度均值 | 0.141 | 0.058 |
| ≥0.3 占比 | 3.7% | 0.0% |
| 骨架种类 | 39~60 | 64 |
| 最高单句复用 | 65 次 | 18 次 |

## 已记录的结论（避免重复踩坑）

- **旧 3 万篇训练语料是引擎自己的输出**：38.5 万句里只有 4361 个不同句，重复率 98.9%。
  用它训练等于让模型学拼接器，已成历史包袱，训练默认排除。
- **模板化分两层**：字句层（同句复用，折返期能治）+ **句式层（换词共用骨架，冷却类机制全治不到）**。
  真实病灶在句式层。
- **`overlap_check` 旧版是恒真的**：逐字精确匹配遇上「现场组装」的句子必然不重合，
  「最多重写 3 次」实为死代码。现版本已改为四层检测。
- **规则分不测质量**：`择优选择.py` 里只有「新颖」一维有信息量，它衡量的是「离参照集多远」，
  不是「写得好不好」。质量梯度要靠真实裁判（`教师裁判.py`）。
- **本机 CPU 训不动**：实测 0.34 token/s，一条 1000-token 样本约 50 分钟。CPU 只用于格式验证。
